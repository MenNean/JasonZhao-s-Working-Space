### 直接文件读取（DSH 无 MCP 时可用）

DSH 先确认其文件工具可访问目录；访问被拒绝时请用户授予对应目录权限，不自行扩大权限。PowerShell 示例须在终端工具执行，不通过桌面自动化输入终端命令：


### 已有只读 MCP 的接口

Codex 中服务名为 `obsidian_memory`，配置指向：

```text
C:\Users\邓庆帅\Desktop\赵浩森临时工作站\全域解决方案部\业务线文件\2026项目\codex\obsidian_knowledge\mcp\obsidian_knowledge_mcp.py
```

| 工具 | 主要参数 | 作用 |
|---|---|---|
| search_notes | query, limit, scope | 按关键词搜索笔记 |
| read_note | path, max_chars | 按库内相对路径或已知 URI 读 Markdown |
| list_projects | 无 | 列有首页的项目目录 |
| get_project_context | project | 读该项目首页与沉淀入口 |
| get_memory_context | query, limit | 组合读启动、偏好、同步 SOP 和搜索命中 |
| get_pending_knowledge_checks | 无 | 查看待沉淀判断队列 |

服务实现核对：仅允许库内 `.md`；读取通常最多 20,000 字符；搜索词空格分隔后按 AND 匹配，默认 20 条，最多 50 条。当前 `scope` 实现会走 Markdown 文件解析，适合指定一份 `.md`；不要把目录名当作已支持的目录范围。目录范围搜索可改用 `rg`。

已知资源 URI：`obsidian://memory/startup`、`obsidian://memory/preferences`、`obsidian://memory/sync-sop`、`obsidian://projects/index`、`obsidian://vault/home`。

该服务“只读”指不改知识笔记；调用会写其现有访问日志。本次只检查代码，没启动该 MCP。DSH 尚未注册此服务，不得声称 `obsidian_memory` 工具已在 DSH 可调用，也不要照搬整个 Codex config.toml。
