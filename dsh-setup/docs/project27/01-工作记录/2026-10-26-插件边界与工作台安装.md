# 插件边界与工作台安装

## 一、Codex 插件没有 DSH 版本对照

| 类型 | Codex 插件 | DSH 现状 |
|---|---|---|
| 文档 | documents / spreadsheets / presentations / pdf / template-creator | 有替代：office 系列技能（LibreOffice Kit），template-creator 无直接对应 |
| 浏览器 | chrome / browser | 无内置，需 playwright-cli 或社区插件 |
| 桌面 | computer-use / unified-computer-use / codex-app-tools | 无对应，需独立接入 |
| 平台 | figma / github | 需 MCP 或 API，本次未接 |
| 运行时 | hyperframes / node_repl | 有技能无运行时；node_repl 用 pwsh/python 代替 |
| 记忆 | obsidian_memory | 服务代码在，未注册 |

结论：插件不是"迁移"，是"重新接入"。

## 二、为什么选最小组合

社区全家桶 `@linxin666/dsh-web-all` 会同时带 SSH 面板、手机远程配对、用量统计和 cron 任务，等于多开几个网络入口。经确认只装两块：

| 包 | 版本 | 作用 |
|---|---|---|
| `@linxin666/dsh-client-ui-task-board` | 0.4.8 | 五列看板 + cron 后台调度 + 验收关卡 |
| `@linxin666/dsh-client-ui-skin-center` | 0.4.8 | 皮肤中心，`$DSH_HOME/skins` 热换肤 |

两个包都声明 `dsh >= 0.2.1-rc.2`，宿主 0.2.1-rc.3 满足；React peer 为 `^18.2.0`。

## 三、安装验证（2026-10-26）

| 检查项 | 结果 |
|---|---|
| `~/.dsh/profiles/desktop/package.json` dependencies | 两个包均已写入 `^0.4.8` |
| `dsh.profile.bundles` | 已追加两条，位于 whale-girl 之后 |
| `node_modules/@linxin666/` | 两个目录存在 |
| 任务看板服务 | `task_board_list` 返回正常，revision 0，空板 |

安装走桌面客户端「设置 → 插件」完成，未使用外部 CLI：官方桌面端对 `desktop` profile 应用内专管，外部修改会被限制或覆盖。

## 四、使用注意

- cron 由后台宿主进程调度，客户端退出或系统休眠的触发点不补跑。
- 任务看板默认带「任务验收」，会额外调用裁判模型产生费用；不需要可在设置里关。
- 版本当前用 `^0.4.8` 浮动范围，不是钉死。出问题时按包名回退上一个版本，或在 profile 的 `pnpm-workspace.yaml` 配 `minimumReleaseAgeExclude: ['@linxin666/*']`。
- 回滚：插件页卸载两个包并重启客户端。
