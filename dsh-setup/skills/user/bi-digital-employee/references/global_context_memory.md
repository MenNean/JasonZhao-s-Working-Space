# 全局变量记忆规则

> 用途：记录真实场景问答中的“会话级全局变量记忆”机制。该机制用于减少重复反问，但不能绕过提需人确认。

## 一、记忆键

全局变量记忆按以下组合键管理：

| 记忆键字段 | 当前规则 |
|---|---|
| `brand_id` | 作为品牌/业务范围记忆维度之一。 |
| `channel` | 作为渠道记忆维度之一；当前所有渠道默认按京东处理。 |

记忆键格式：

```text
brand_id + channel
```

示例：

```text
A + 京东
```

## 二、可记忆的全局变量

| 变量 | 是否可记忆 | 说明 |
|---|---|---|
| `shop_id` | 是 | 查询权限和店铺范围。 |
| `brand_id` | 是 | 用于会话记忆分组或额外业务范围限制；不作为订单表关联会员表的默认关联条件。 |
| `channel` | 是 | 当前默认京东。 |
| 订单状态 | 是 | 例如有效订单、完成订单。 |
| 时间字段 | 是 | 例如下单时间 `order_start_time`、支付时间 `pay_confirm_time`。 |
| 订单类型 | 是 | 例如全量订单、过滤购物金、过滤赠品等。 |
| 新客/老客口径 | 是 | 例如历史新老客、365 新老客、180 新老客。 |
| 会员限制 | 是 | 例如是否限制先开卡后下单。 |

## 三、确认规则

1. 首次提问时，如果提需人补充了全局变量，需要将这些变量写入当前会话上下文。
2. 后续提问时，如果命中同一个 `brand_id + channel` 记忆键，AI 应把上次确认过的全局变量带出来，请提需人确认是否沿用。
3. 提需人未确认前，不能静默沿用可能影响 SQL 结果的变量。
4. 如果提需人明确说“不调整”“沿用上次”“同上”，则可以使用记忆值生成 SQL。
5. 如果提需人修改任一变量，则用新值覆盖当前记忆键下的对应变量。

## 四、当前会话记忆样例

| 记忆键 | 变量 | 当前值 | 来源 |
|---|---|---|---|
| `A + 京东` | `shop_id` | 小寒test | RS001 用户补充 |
| `A + 京东` | `brand_id` | A | RS001 用户补充 |
| `A + 京东` | `channel` | 京东 | 当前所有渠道默认京东 |
| `A + 京东` | 订单状态 | 完成订单 | RS001 用户补充 |
| `A + 京东` | 时间字段 | 支付时间 `pay_confirm_time` | RS001 用户补充 |
| `A + 京东` | 订单类型 | 过滤购物金订单，`sku_id != 'test购物金'` | RS001 用户补充 |
| `A + 京东` | 新客/老客口径 | 历史新老客 | RS001 用户补充 |
| `A + 京东` | 会员限制 | 不限制先开卡后下单 | RS001 用户补充 |

## 五、反问话术模板

```text
我检测到当前可能沿用上次的全局变量：
- brand_id：{brand_id}
- 渠道：{channel}
- shop_id：{shop_id}
- 订单状态：{order_status}
- 时间字段：{time_field}
- 订单类型：{order_type}
- 新老客口径：{customer_segment}
- 会员限制：{member_limit}

请确认本次是否沿用以上口径；如有调整，请直接说明需要调整的项。
```
