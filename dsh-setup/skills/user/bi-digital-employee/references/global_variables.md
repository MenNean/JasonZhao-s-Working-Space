# 全局变量知识库

> 来源：`全局变量+指标矩阵原始文档.xlsx` 的 `全局变量` sheet。

## 一、变量清单

| 变量 | 定义/可选项 |
|---|---|
| 渠道 | 全渠道、京东、天猫、抖音；当前所有渠道默认京东 |
| brand_id | 品牌/业务范围记忆维度；用于全局变量记忆键，不作为订单表关联会员表的默认关联条件 |
| 店铺id | shop_id=？ |
| 订单类型 | 1、全量订单<br>2、正常订单（增加剔除赠品sku_id not in、购物金sku_id not in、20元以下订单group by到order_id，sum（sku_amt_jd）<20）<br>3、剔除赠品sku_id not in<br>4、剔除购物金sku_id not in<br>5、剔除20元以下订单group by到order_id，sum（sku_amt_jd）<20 |
| 订单状态 | 1、完成：order_status_id IN (4, 105, 120, 121)<br>2、有效：order_status_id NOT IN ('5', '106', '109', '112', '113', '115', '118', '124', '128', '201')<br>3、其他order_status_id in （自选） |
| 时间 | 1、下单时间（order_start_time）<br>2、支付时间（pay_confirm_time） |
| 会员限制 | 1、限制-先开卡后下单（订单表关联会员表，group by到cjyx_encrypt_pin，有效订单计算时间要晚于open_card_time）<br>2、不限制-先开卡后下单（订单表关联会员表）<br>3、结束时间前开卡（open_card_time早于提需人提出的查询时间窗的结束时间前） |

## 二、完整性说明

全局变量用于定义每次查询前必须确认的参数框架，但并不代表所有变量都已经具备完整可执行 SQL 条件。

| 变量 | 当前理解 | 后续处理 |
|---|---|---|
| 店铺id | `shop_id=?` 说明查询必须带入店铺/品牌权限边界，但当前未提供品牌与 `shop_id` 的完整映射表。 | AI 需要向提需人确认具体品牌或店铺，并在获得对应 `shop_id` 后才能执行查询。 |
| brand_id + 渠道 | 用于会话级全局变量记忆。当前渠道默认京东，记忆键为 `brand_id + channel`。 | 首次提问补充参数后，后续同一记忆键下的提问需要带出上次确认值，请提需人确认是否沿用。 |
| 订单类型 | 当前给出的是订单过滤方向，不是完整码值表或完整 SQL 条件。 | 需要结合具体资产补充：赠品 SKU 列表、购物金 SKU 列表、20 元以下订单过滤逻辑，以及“正常订单”的组合规则。 |
| 订单状态 | 已提供完成订单、有效订单和自选状态的基础规则。 | 默认使用有效订单；如用户选择完成订单或其他状态，再按对应规则处理。 |
| 时间 | 已提供下单时间和支付时间。 | 默认使用下单时间 `order_start_time`；如用户明确选择支付时间，则改用 `pay_confirm_time`。 |
| 会员限制 | 已给出三类会员时间限制，但仍需要结合查询问题判断是否启用。 | 如用户问题涉及会员身份、新老会员、开卡后购买等，需要反问或自动识别会员限制口径。 |

因此，`店铺id` 和 `订单类型` 属于“需要业务补充或反问确认”的全局变量，不能直接假设已经完整；`订单状态` 和 `时间` 则可以作为当前第一版较稳定的默认参数。

## 三、默认规则

- 默认权限过滤字段：`shop_id`。
- 默认渠道：京东。
- 默认业务时间：下单时间，即 `order_start_time`。
- 默认订单口径：有效订单。
- 数据延迟：T+1，早上 9 点前通常完成前一天数据同步。
- 敏感字段仅用于去重、关联、过滤，不允许明细展示。
- 每次新的查询需求都要重置全局变量，并通过提问向提需人确认。
- 支持按 `brand_id + 渠道` 记忆上次确认的全局变量；下次提问时可以带出默认值给提需人确认，但不能在未确认的情况下静默沿用。
